# Career Autopilot — UI Layout & Information Architecture

> **定位:** 本平台的核心价值是 **全自动找工作 + 全自动投递工作(autopilot)**。
> 因此 UI 不是一个"让用户手动刷职位的招聘网站",而是一台**自动化机器的控制台**。
> 所有布局决策都服从一条原则:
>
> **主舞台留给「机器的运行状态」与「人工闸门」;配置类(数据源/筛选)一律降级。**

相关文档:运行机制见 [`AUTOPILOT-DESIGN.md`](./AUTOPILOT-DESIGN.md)(autopilot 填到 100% 后停在人工 Submit 闸门)。

---

## 1. 心智模型:Autopilot 闭环

```
       ┌─────────────────────────────────────────────┐
       │   你配置一次 (Profile: 简历/偏好/Q&A/数据源)    │
       └─────────────────────┬───────────────────────┘
                             ↓
   ┌──── 机器自动跑(你不用管)─────────────────────────┐
   │  扫描数据源 → 筛选 → 自动填表 → 停在人工闸门         │
   └─────────────────────────┬─────────────────────────┘
                             ↓
       ┌─────────────────────────────────────────────┐
       │  只在「闸门」找你:① 点 Submit ② 回答新问题      │  ← 用户唯一每天要做的
       └─────────────────────────────────────────────┘
```

用户每天只做两件事:**批准提交** + **回答机器不会的新问题**。其余全自动。
→ 所以日常主舞台是 **Dashboard(控制台)** 和 **Review(人工闸门队列)**,而不是职位网格。

## 2. 全局框架(所有页面共用)

```
┌────────────────────────────────────────────────────────────────────┐
│  💼 Career Autopilot          AUTOPILOT ●━━ ON    ⏸ Pause   👤 Victor │ ← 顶栏:全局开关常驻
├────────────────────────────────────────────────────────────────────┤
│  🏠 Dashboard   ✅ Review ③   📋 Jobs   📨 Tracker   ⚙️ Profile        │ ← 主导航 + 待办角标
├────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                          [ 页面主体 ]                                 │
│                                                                      │
└────────────────────────────────────────────────────────────────────┘
```

- **Autopilot 总开关**放在最顶栏右上角、**全局常驻**,任何页面一眼可见机器开/关 —— 这是"全自动"产品的灵魂控件。
- **Review** 带未读角标 `③`,提醒用户有几个闸门待处理。

- 活动流让用户"看得见机器在干活",建立信任。
- 数据来源:`/api/career/finder/pipeline`、`/scan/status`、applications store。

## 4. 各功能归位表

| 功能 | 现在位置 | 自动化版应去的位置 | 理由 |
|------|----------|--------------------|------|
| Autopilot 开关/状态 | ❌ 无可视化 | **顶栏全局 + Dashboard 主位(新建)** | 全自动产品的灵魂控件 |
| 人工闸门(Submit/新问题/失败) | 散在 Apply 页 | **Review 队列(新建,带角标)** | 用户每天唯一要做的事 |
| Sources(Portals)配置 | Find Jobs 顶部 + Settings | **Profile**;Jobs 页只留状态条 | 低频配置 |
| Filters 配置 | Find Jobs 折叠区 | **Profile 完整版 + Jobs 侧栏精简版** | 自动化筛选标准,降级 |
| 候选职位列表 | Find Jobs 主体 | **Jobs 页(降级为透明度)** | 不再是日常驱动 |
| Applied / Tracker | Apply & Track | **Tracker** | 结果追踪 |
| Interview Prep | Advanced(藏) | **升为主功能或并进 Tracker** | 真实用户功能,不该藏 |
| Overview/Pipeline/Shortlist (legacy) | Advanced | **删除** | 已被新结构取代 |
| Learning / Iteration (debug) | Advanced | **Profile → Dev/Debug,或 ?debug** | 不该和用户功能混在导航 |

## 5. 旧 vs 新 一句话对比

|  | 旧(手动浏览感) | 新(自动化感) |
|---|---|---|
| 落地页 | Find Jobs 职位网格 | **Dashboard 控制台** |
| 每天用的页 | 刷卡片点 Apply | **Review 人工闸门队列** |
| 职位列表 | 主舞台 | 降级成透明度页 |
| Sources / Filters | 挤在顶部碍眼 | 沉到 Profile,只留状态条 |
| Autopilot 状态 | 看不见 | 顶栏全局常驻 |

## 6. 建议落地顺序

1. **Dashboard**(autopilot 状态卡 + 4 个漏斗数字 + 活动流)—— 立刻把产品"变成全自动的样子"。先静态布局接现有 API,再填实时数据。
2. **Review 队列**(收拢 Submit 闸门 + 新问题 + 失败接管)—— 用户每天真正用的页。
3. **Jobs 降级**(Sources→状态条,Filters→左栏,Apply→"让机器投")。
4. **导航重排 + Profile 归类**(删 legacy,debug 页收进 Dev/Debug)。

> 顶栏全局 Autopilot 开关随 1 一起落地,因为它是贯穿全局的状态。
